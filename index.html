Security

OpenClaw Security Hardening — GTA.
Security is the baseline, not a feature.

An AI with access to your email, calendar, and business tools is a high-value attack surface. We configure every deployment with this reality in mind — not as an afterthought.

🏗️ Your infrastructure, not ours

Every deployment runs on client-owned infrastructure. VPS, Mac Mini, local server, cloud VM — your choice. Your data never touches our systems at any point during or after installation.

⏱️ Temporary access, permanent cleanup

We need temporary access to install and configure. After delivery, we remove all access and walk you through credential rotation. There is no persistent backdoor access. Ever.

🔑 No raw credential handling

All OAuth tokens are managed via Composio middleware. The agent never sees your raw credentials. You retain full revoke capability from the Composio dashboard — one click kills any integration.

📋 Documented and auditable

We enable audit logging from day one. You know what the agent is doing, when it's doing it, and what it has access to. Governance is built into the deployment, not added later.

Security hardening checklist

Every deployment we deliver completes this checklist before handover.

01

Docker sandboxing configured

The agent runs in a containerized environment with resource limits, network restrictions, and filesystem isolation. It cannot access your host system arbitrarily.

02

Exec allowlist enforced

We configure an explicit allowlist of permitted system commands. The agent cannot execute arbitrary code or shell commands outside the approved list.

03

Firewall rules in place

Inbound and outbound network rules configured to match your environment and the agent's actual access requirements — nothing more.

04

Read-only permissions as default

We start with the minimum viable permissions — read-only email, no send capability. Permissions expand gradually as you test and build confidence in the agent.

05

Composio OAuth middleware installed

All tool integrations run through Composio. The agent authenticates through a middleware layer — never handling your raw credentials directly.

06

Audit logging enabled

Full audit trail configured and tested. You can see what the agent accessed, what actions it took, and when — at any time.

07

Update cadence established

We document the recommended update process and timing for OpenClaw releases. You know how to maintain security posture over time — or we do it for you under Managed Support.

08

Credential rotation completed post-delivery

After installation, we walk you through rotating any credentials that were used during setup. Our access window is closed before handover is considered complete.

09

Safe operating procedures documented

Your runbook includes security-relevant operating procedures — how to revoke integrations, how to update safely, what to do if something looks wrong.
